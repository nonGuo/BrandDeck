=== PARSING TRAPS FOUND IN THIS FILE ===
 - dk1 == lt1 == #1D1D1A and dk2 == lt2 == #FFFFFF: the light/dark pairs are duplicated, so bg1 (lt1)
   and tx1 (dk1) are the SAME colour, and so are bg2 (lt2) and tx2 (dk2). A parser that
   assumes lt1=#FFFFFF / dk1=#000000 will invert every text and background colour here.
 - sldSz cx=12196763, not the canonical 12192000 -> width is 13.3385 in, not 13.3333 in (+0.00521 in).
 - There are 4 slide masters and 6 themes. "The" theme is theme1 only because ppt/_rels/presentation.xml.rels
   rId14 points at it. theme2 (master2) really differs in accent2..accent6 and hlink/folHlink:
   C8102E / EA594F / F8B53C / 231815 / 595757, hlink 898989, folHlink B5B5B5.
 - theme3 (master3, used by the real content pages) differs in lt1=#666666 and lt2=#EBEBEB.
 - theme5/theme6 (notes/handout masters) use <a:sysClr val="windowText" lastClr="000000"/> and
   <a:sysClr val="window" lastClr="FFFFFF"/> - a parser must read lastClr, not @val; and lastClr
   is OPTIONAL in the schema, so the code path that reads it can be missing it.
 - <a:ea typeface=""/> and <a:cs typeface=""/> are EMPTY STRINGS in both majorFont and minorFont;
   the real CJK face lives in <a:font script="Hans"> (majorFont 微软雅黑, minorFont 黑体).
 - Master txStyles override the theme: master1 title = Microsoft YaHei (NOT the theme face "Arial Black").
 - image1.png is referenced by TWO masters (slideMaster1 rId6 and slideMaster4 rId3), so "media part
   referenced by exactly one master" is not a valid logo heuristic here.
 - The logo is a userDrawn <p:pic> on the master with no <p:ph>, placed BOTTOM-right, not top-left.
 - Layouts 1-4 have NO <p:bg>: the background comes from the master. Layout5 bg=#EBEBEB, layout7 bg=#FFFFFF.
 - No <p:sldLayout> carries a @type attribute; identify layouts by cSld/@name (Chinese names present).
 - Most slide placeholders carry NO <a:xfrm> -> geometry must be resolved slide -> layout -> master by
   (type, idx); <p:ph> @idx is absent on some placeholders (defaults to 0) and @type is absent on others.
 - slideMaster2 has an EMPTY spTree (no placeholders at all) - a master with zero shapes is legal.
 - slideMaster3 holds group shapes (<p:grpSp>, nested 3 deep) pushed off-canvas at x=13.3599 in
   (slide is 13.3385 in wide): a brand colour-swatch board. Naive bbox walks report out-of-page shapes.
 - Group shapes have chOff/chExt != off/ext, so child coordinates need the affine transform.
 - Near-miss hex values: theme accent1=C7000A but the layouts paint C7000B; master1 body text uses
   1D1D1B while theme dk1 is 1D1D1A; master3 swatch board uses C8102E. Do not "normalise" these.
 - slide4 mixes an <a:tbl> graphicFrame, a <p:graphicFrame> chart and a text box rotated -20 deg.

   layout1 -> master1 -> theme1; slide2 layout5 -> master2 -> theme2; slide5 layout7 -> master4.

 - No themeOverride*.xml parts exist (checked); docProps/custom.xml holds opaque DRM-looking strings.
